# Scope and acceptance

The first native execution path is Gemini CLI 0.43.0 + GEMINI_API_KEY + gemini-3.8-flash. Root experiment model/settings apply to both arms, with no per-arm model selection. A/A duplicates the harness instruction treatment; A/B changes that treatment. The existing generic command protocol remains a provider-neutral integration boundary; introducing a router/role roster is out of scope.

Each attempt starts with fresh workspace, HOME and GEMINI_CLI_HOME. No ambient login/API keys, user/project hooks, skills, extensions or MCP are imported. Detect managed system settings rather than bypassing them. Configuration is explicit and reproducibly retained; actual loaded behavior remains evidence-based. Use fixed read-only tools and no permission bypass. Generated Go grading is still local code execution, and a temp directory is not a security sandbox.

Installed stream-json drops thoughts counts; JSON output preserves per-model token counters including thoughts. Use JSON with native output retention, unknown usage on interruption/truncation/malformed data, and report normalized input as prompt plus tool-use prompt and output as candidates plus thoughts without double-counting cached input. Gemini CLI internally defaults some absent upstream fields to zero; present counters are CLI-reported evidence, not proof of provider billing completeness. Require explicit API request/error counters; failed requests have no dependable usage and therefore invalidate normalized completeness even when the final response succeeds. Never reconstruct thought tokens from total-input. Unexpected or absent per-model accounting stops the pilot and cannot count as a valid same-model quality observation.

Verification: fake native invocation tests for API-key-only environment/config isolation, complete/failed/partial/malformed/overflow output, model mismatch, cache/thought accounting, cancellation and partial rescore; non-destructive mutation checks; independent review; full clean-tree gates and doctor. Live calibration still requires the user-specified monetary cap. No model/paid calls are authorized by this implementation plan.
