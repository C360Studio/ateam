## 1. Implementation

- [x] 1.1 `bootstrap.attributeMCPProcesses` runs after the `ps` scan in `InspectRunningMCPProcesses` (doctor) and `InspectClientMCPProcesses` (hook): a process is this root's when `state.LoadLiveMCPProcesses(root)` lists its PID, or when its working directory is readable and `state.InRepository(root, cwd)` holds; otherwise `state.MCPProcess.Repo` is `other` (`"repo": "other"` in doctor's `running_mcp_processes`) and `CheckRunningMCPProcesses` / `CheckClientMCPProcesses` skip it. The working directory comes from `bootstrap.readProcessCwd` (`os.Readlink("/proc/<pid>/cwd")` on Linux; `lsof -a -p <pid> -d cwd -Fn` on macOS, 500ms timeout, about 20ms per call) and only for PIDs absent from the registry; an unreadable one, or any other OS, keeps today's warning. `state.InRepository` reuses `mcpCandidateRoots` (this root, the main checkout, and every linked worktree from `<common dir>/worktrees/*/gitdir`, read from files with no git subprocess) and matches the directory or a subdirectory of one, comparing raw and symlink-resolved paths (#151). The premise that `LoadLiveMCPProcesses` itself falls back to a process scan is off: the scan is in `internal/bootstrap`, so attribution lives there.
- [x] 1.2 `hook.checkSessionStaleMCPOnce` returns before the session check and the `ps` scan unless `bootstrap.IsAteamCheckout(root)` holds, so the `MCP server PID n (build x) is older than HEAD; restart the client` line prints only in the ateam checkout (#151 comment 6388138323). The hook path's `lsof` cost is paid once per session, in the ateam checkout, per unregistered MCP process in the client tree; `TestHookLatencyBudget` and doctor's latency probe send no `session_id` and do not reach it.
