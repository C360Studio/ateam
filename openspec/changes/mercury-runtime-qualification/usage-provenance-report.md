# Provider-usage provenance: offline evidence contract

## Result and boundary

PR #64's accounting blocker is reproducible without the CLI or bridge: the retained low/high provider responses each explicitly report 20 input, 5 output, 3 cached and 2 reasoning tokens. The missing case reports no usage, even though the translated CLI counters were 26/4. The new reader credits a **known subtotal of 40 input / 10 output across three supplied exchanges**, with one unknown exchange. It neither credits the 26/4 estimates nor adds cache/reasoning subsets again.

This delivers a viable **offline interpretation contract**, not a qualified live capture path. The source audit does not establish a supported flag that makes Claude terminal counters authoritative. The next integration gate is proving reliable pre-normalization capture and correlation of every request/attempt, including cancellation and logging failure. No bridge fork, replacement runtime, network proxy, provider call, new package installation or production adapter is added. All prior runtime evidence, lock/stack and Gemini artifacts remain unchanged. #58 stays open.

## Executable research contract

`offline/usage_provenance.py` accepts an in-memory list of exchanges; it does no I/O or network work. Each exchange has exactly `exchange_id`, `attempt_id`, `body`, `body_sha256`, `http_status`, and `termination`. The IDs are capture-owned labels, not provider response IDs. Repeated provider IDs across different exchanges do not deduplicate retries. A duplicate capture exchange ID, bad schema/hash or exceeded size bound refuses the supplied history, rather than returning misleading totals. The caller must retain the original manifest/body on refusal; the function does not persist evidence.

The SHA-256 binds interpretation to the supplied UTF-8 body; it does **not authenticate origin** or prove that no exchange was omitted. The source label is deliberately `supplied-provider-wire`. A future collector must establish source placement, request binding, endpoint identity and exhaustive capture independently. PR #64's three case names are replay labels, not newly observed capture IDs. Provider HTTP 200/eof inputs for that replay come from the fixed synthetic stub behavior and complete retained frames; this is not retrospective proof of a production ledger.

The finite supported profile is LF/CRLF UTF-8 SSE, one JSON data line per event, choice index 0, one finish event, at most one non-null usage object on a subsequent empty-choices event, then `[DONE]`. Comments are accepted. Unfinished events, malformed/duplicate-key/nonfinite JSON, unexpected model/ID changes, extra data after DONE, duplicate usage (even identical), incompatible totals/subsets and unsupported framing are invalid. Counts must be nonnegative integers up to 2^53−1; booleans are rejected. Unsupported profiles refuse completeness; this is not a general SSE parser. Bounds are 1 MiB per body, 256 supplied exchanges and at most 4096 split SSE segments (including the trailing segment).

Raw usage objects and explicit primary/cache/reasoning fields are kept separately. Absent and JSON-null values both mean unknown in normalized fields, while raw usage/body retains their presence distinction. Explicit zero is retained. Extra provider detail keys remain in raw usage and are not interpreted as comparable tokens. `usage_state` distinguishes missing, reported and invalid; `primary_complete` additionally requires explicit prompt/output counts, valid framing, DONE and successful HTTP 200/eof. `details_complete` requires cached/reasoning counts too; missing detail does not erase known primary counts. Total tokens is optional and never synthesized as provider-reported data. When present, total and subset consistency is checked.

Cancellation, timeout, disconnect or absent DONE preserves any valid observed usage for diagnostics while withholding complete primary credit. Non-200 error bodies are retained by the caller/hash but their usage shape is unsupported and unknown. A known subtotal includes only complete exchanges. It is not a billing total or a lower bound on monetary spend. Unknown exchange IDs remain visible even after a successful retry. All supplied histories return `runtime_qualified: false`; `supplied_inventory_complete` says nothing about unobserved requests, native execution success or price coverage. CLI/bridge estimates are never accepted as an alternate source.

- **Decision:** exhaustive bounded generated examples plus independent fixed expectations; no random fuzz campaign. The finite parser deliberately refuses broader profiles.
- **Rule:** only explicit, valid provider counts can be credited once per separately identified exchange; absence, interruption, ambiguity and estimates cannot establish completeness.
- **Inputs:** retained low/high/missing responses; 81 combinations of absent/zero/positive primary/subset fields; six finish/usage/DONE permutations; eight termination/DONE combinations; six known/missing/cancelled history permutations; duplicate usage/IDs, repeated provider IDs, errors/retry, malformed input and resource boundaries. Fixed expected counts come from fixture authorship, not the implementation. History expectations use test-owned classifications and preserve supplied order.
- **Run:** 14 contract tests pass, with explicit completed-grid/boundary counts in stdout. Seed replay/random exploration: neither; the Cartesian/permutation enumeration is deterministic. Prior replay also passes with its blocker intact. Exact commit and full repository verification/review results are recorded in PR #69; local logs use `.enjoy-logs/usage-*` and `sentinel-cwd-*`.
- **Mutation:** eleven copied-reader mutations detected: exponent overflow, impossible partial-total lower bounds, missing→zero, ignored cancellation, double-counted reasoning, accepted duplicate usage, provider-ID deduplication, lost reasoning detail, ignored hash, bool-as-count and ignored byte limit. Cwd-guard omission also detected. Baseline/after pass and unchanged original SHA-256 are checked by the runner; no destructive git operations. These test contract sensitivity, not upstream bridge-source mutation coverage.
- **Not covered:** actual transport/callback instrumentation, partial usage in non-200 bodies, arbitrary SSE profiles, timing/byte fragmentation, native tool/permission/cancellation histories, native skills, price/billing, live provider behavior or a second runtime. Research Python tests are opt-in and are **not executed by ordinary Go/Vitest CI**.

The PR #64 nit is fixed: `check_sentinel.py` resolves and checks its test root is under the user home before creating files or relying on home-denial policy. Regression first failed for out-of-home and symlink-escaped roots with `read escaped`; valid worktree passed. After the guard, all three pass. An initial sandboxed attempt could not apply nested Seatbelt (`Operation not permitted`); that was inconclusive, and the explicit approved run established the meaningful RED/GREEN results. The reproducer itself is unchanged.

Independent native Codex plan review passed before implementation, with no blocking findings. Change review found a medium exponent-overflow hole (`1e999` in otherwise valid raw JSON) and a low partial-total/subset inconsistency. Both had failing regressions before correction: finite-float parsing now rejects overflow anywhere, and subset-derived lower bounds cannot exceed total while absent primary fields remain unknown. Both also have detected copied-source mutations. Reviewer exact model/effort are unavailable; read-only behavior was observed, not OS-enforced. No configured stronger-model policy exists. Final exact-head technical review and verification belong in PR #69; the owner arranges cross-service review before merge.
