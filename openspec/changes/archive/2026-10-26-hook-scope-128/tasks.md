## 1. Implementation

- [x] 1.1 With `ATEAM_HOOK_SCOPE=user`, `checkHookConfigs` accepts the Claude hooks from `.claude/settings.local.json` or `~/.claude/settings.json` when `.claude/settings.json` lacks them; unset, behaviour is unchanged (#128). `inspectHookConfigs` walks `hookClients` (Claude, Codex, Gemini, Antigravity); `checkHookConfigs` (the `CheckParity` path) and the new `HookSources` both read it, and `checkAntigravityConfigs` keeps only the plugin files. Each file goes through one `hookFileViolations` (valid JSON, every required `ateam hook --event <event>`, the client's `--agent`), so a user-scope file gets exactly the project file's checks. Decisions: hooks split across files fail, because each file is checked on its own and the first file that passes every check wins (project, then `.claude/settings.local.json`, then `~/.claude/settings.json`); when none passes, doctor reports the project file's violations and every user-scope file's. The value is trimmed and lower-cased as `ATEAM_FORGE` is; any value other than `user` is the violation `ATEAM_HOOK_SCOPE=<value>: unknown value; set it to user or unset it` and doctor reads only the project files, so a typo does not fail with a misleading `missing hook command`. `~` resolves through `os.UserHomeDir`; when it fails the file is `<label>: cannot resolve the home directory`. Gemini's `contextFileName` is checked on the project file as before, or on the user file that carried the hooks when the project file lacks it (Gemini merges its settings layers).
- [x] 1.2 Doctor reports the file that satisfied each client's hook check. Codex and Gemini read a user-scope hook file only where the client supports one (verify against each client's documentation and record the source); otherwise doctor reports that the client has no user-scope hooks (#128). Doctor's JSON gains `hook_sources`, an object from client agent (`claude`, `codex`, `gemini`, `agy`) to the file that passed, holding only clients that passed and `{}` (never `null`) when none did. Sources, read 2026-10-26: Codex documents `~/.codex/hooks.json` as a user-level hook file and loads every layer's hooks ("If more than one hook source exists, Codex loads all matching hooks"), https://learn.chatgpt.com/docs/hooks (the target of https://developers.openai.com/codex/hooks), so doctor reads `~/.codex/hooks.json` (not `$CODEX_HOME`, which that page does not mention, and not inline `[hooks]` in `config.toml`, which `ateam init` does not write). Gemini CLI merges hooks from project `.gemini/settings.json`, user `~/.gemini/settings.json`, system `/etc/gemini-cli/settings.json` and extensions, https://geminicli.com/docs/hooks/, so doctor reads `~/.gemini/settings.json`. Antigravity documents a global `~/.gemini/config/hooks.json`, https://antigravity.google/docs/hooks, but #128 names only the three clients, so doctor reads no user-scope file for `agy` and reports `.agents/hooks.json: ATEAM_HOOK_SCOPE=user, but agy has no user-scope hooks doctor reads` (a `// shortcut:` marks the deferral); this is the client-without-user-scope-hooks case.
