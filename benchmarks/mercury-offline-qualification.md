# Mercury Go integration: offline checks

PR #77 implements the existing single-file benchmark flow in `internal/bench`. Go owns execution, capture and accounting. The embedded Python callback and its inline Python test are removed. Identified ignored research scripts (the legacy cleanup probe, teardown driver/hook/guardian, and abandoned guardian copies) are removed too. The installed vendor environment and earlier archived research are preserved as historical evidence; neither archived scripts nor a custom Python hook execute in this benchmark path.

## Actual pinned path

On October 21, 2026, `TestMercuryPinnedOffline` ran actual Claude 2.1.292 → LiteLLM 1.99.0 → the in-process Go capture proxy → a local Go provider fixture. Fake credentials and macOS `sandbox-exec` denied external networking and keychain access for the test process and descendants. The fixture observed one `/v1/chat/completions` request: `mercury-3`, low effort, 8192 output allowance, with `Read` and `StructuredOutput` tools. The proxy handles LiteLLM's `HEAD /` probe locally. Config requests zero SDK retries using `allowed_openai_params: [max_retries]` and `max_retries: 0`, without a callback. The successful fixture observed retry count zero; it does not independently prove the SDK retry maximum. Go separately rejects retries before provider dispatch. Native schema extraction, provider usage 20 input/5 output (cached 3/reasoning 2), and envelope replay passed. This qualifies the new Go path independently of the earlier callback run; it is not model-quality or billing evidence.

The native executable SHA256 was `97a01e5bc74a199e67189435d0331ea3a24eac2e07db4b76d9148c5b0386138f`. Existing isolated Python 3.14.5/HTTPX 0.28.1/OpenAI 2.54.0 dependencies were reused; no installation or upgrade occurred. Executable hashes and versions do not authenticate every transitive dependency. The provider key stays in Go; the bridge and native process receive only local tokens.

The opt-in test is skipped in ordinary CI. Build the Go test binary (`go test -c ./internal/bench -o .ateam/mercury-bench.test`), supply `ATEAM_MERCURY_NATIVE_OFFLINE=1`, `ATEAM_MERCURY_CLAUDE` and `ATEAM_MERCURY_BRIDGE` pointing to pinned executables, and run only `TestMercuryPinnedOffline` with a 60s test timeout under an external-network-denying OS policy. `ATEAM_MERCURY_EVIDENCE` optionally names an ignored private directory for the envelope/diagnostics. Production configuration has no endpoint override.

## Go checks

Go helper processes forward real HTTP through the proxy. Tests cover grading and immutable replay; missing/oversized provider usage; absent/oversized capture files; fixed route, credential separation, conflicting output controls, retries and failed-exchange refusal; request/journal limits; dry-run and bridge identity revalidation. Cancellation/timeout tests synchronize on a provider socket handshake and assert closure when the attempt ends. The fixture consumes the request body before waiting for disconnect and has bounded cleanup.

Native stdout/stderr truncation is retained in the Mercury envelope, fails accounting, and reconstructs during replay even when native JSON is truncated. An initial sandbox-restricted regression failure did not prove this bug because listener binding was denied; the authorized Go overlay mutation is the assertion-activation evidence. Proxy shutdown returns latched failure independently of journal persistence, including a regression where both append and truncation fail on a read-only file containing earlier valid usage. Cleanup now lives in the single finish path, which stops and waits for both bridge and proxy before reading capture or diagnostics.

Decision: deterministic examples cover finite controls and ordered histories, without a separate research framework. Rule: validate before dispatch; after any failed exchange, refuse further dispatch and accounting; retained raw envelopes must reproduce responses. Inputs: malformed/duplicate controls, retry counts, 1..5 exchanges, success→failure→request, cancellation, byte boundaries, partial usage and native truncation. Run: focused Go tests, race tests and the opt-in native schema check; exact commands and head are recorded on the PR. Mutation: Go overlay checks detected removal of native truncation forwarding and the retry guard, with passing baseline and after-run checks; see the current PR evidence. Not covered: generalized multi-turn tools, production streaming latency, remote cancellation/billing finality and untrusted OS containment.

The [canary/A/A proposal](mercury-canary-plan.md) needs separate spending authorization after review. Buffered capture changes streaming timing; report task outcomes/end-to-end runtime only. Direct native configurations and frozen Gemini evidence remain unchanged.
