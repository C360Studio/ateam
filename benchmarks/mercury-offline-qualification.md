# Mercury Go integration: offline checks

PR #77 implements the existing single-file benchmark flow in `internal/bench`. The uncommitted Python guardian was removed; Python is limited to the embedded bridge capture callback. Earlier research stays archived and is not the benchmark execution path.

## Actual pinned path

On October20,2026, `TestMercuryPinnedOffline` ran the actual Claude2.1.292 → LiteLLM1.99.0 stack through the new Go runner, with fake credentials and a local Go HTTP fixture. macOS `sandbox-exec` denied external networking and keychain access for the test process and descendants. The fixture observed one non-inference `HEAD /` connectivity probe and one `/v1/chat/completions` model request: `mercury-3`, low effort,8192 output allowance, with `Read` and `StructuredOutput` tool names. It returned a synthetic `StructuredOutput` call containing the existing safe-path reference source and provider usage20 input/5 output (cached3/reasoning2). Native schema extraction, Go accounting and envelope replay passed. This is integration evidence, not model-quality or billing evidence.

The first run reached the same schema/accounting result but its fixture mistakenly counted the HEAD probe as a model request; the corrected fixture distinguished it and passed. No paid endpoint was reached. The native executable SHA256 was `97a01e5bc74a199e67189435d0331ea3a24eac2e07db4b76d9148c5b0386138f`. Existing isolated Python3.14.5/HTTPX0.28.1/OpenAI2.54.0 dependencies were reused; inspected installed source pins matched PR71's retained source hashes. No installation or dependency upgrade occurred. The public `ateam bench run ... --dry-run` also resolved the actual pinned executables without credentials or inference; its first launch lacked the Go grader on the restricted PATH, and the corrected explicit PATH passed. Launcher/hook hashes and versions do not authenticate every transitive dependency.

The opt-in test is skipped in ordinary CI. To reproduce, build the Go test binary (`go test -c ./internal/bench -o .ateam/mercury-bench.test`), supply `ATEAM_MERCURY_NATIVE_OFFLINE=1`, `ATEAM_MERCURY_CLAUDE` and `ATEAM_MERCURY_BRIDGE` pointing to the pinned executables, and run only `TestMercuryPinnedOffline` with a60s test timeout under an external-network-denying OS policy. `ATEAM_MERCURY_EVIDENCE` optionally names an ignored directory for the envelope/diagnostics; keep it private. The default fixture URL is generated by the test; production configuration has no endpoint override.

## Go checks

Ordinary tests use Go helper processes and local HTTP fixtures. They cover source grading and immutable replay, missing/partial/absent/oversized journals, provider controls/model/usage boundaries, credential isolation, bridge-version/hash revalidation and dry-run without inference. Cancellation and timeout tests wait for a provider socket handshake, then assert the bridge-owned connection closes when the attempt ends. Both use the same existing Go process helpers as other adapters.

Meaningful regressions caught and corrected two runner bugs: outer attempt deadlines were initially labelled cancellation, and a capture-file read failure after successful native execution was initially retained with `completed` status instead of `adapter-error`. The latter now passes `RunExperiment` → `LoadExperimentRun` for absent and oversized capture files.

Decision: explicit examples and finite request/history boundaries; no standalone parser-fuzzing framework. Rule: complete provider accounting is required before grading, and raw envelopes must reproduce the same response. Inputs: zero/missing/partial/invalid counts, cache/reasoning subsets,1..5 exchanges, duplicate/out-of-order records, EOF/DONE, exact journal size, native failures and cancellation/timeout. Run: focused Go tests plus the opt-in pinned-native schema check; full verification evidence is on the PR. Mutation: existing Go overlay checks detect removing the runner-error veto and replacing usage aggregation with assignment, with baseline/after passes and unchanged originals. Not covered: generalized multi-turn tools, production streaming latency, remote cancellation/billing finality and untrusted OS containment.

The [canary/A/A proposal](mercury-canary-plan.md) requires separate spending authorization after review. Buffered capture changes streaming timing; report task outcome/end-to-end runtime only. Existing native configurations and frozen Gemini evidence are unchanged.
