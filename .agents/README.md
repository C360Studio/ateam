# Agent & Platform Configuration (`.agents/`)

`.agents/` holds the single set of instructions, workflow rules, and skills shared across **Claude Code**, **Codex CLI**, **Gemini CLI**, and **Antigravity (`agy`)**. The files under `.claude/`, `.codex/`, and `.gemini/` are thin pointers generated by `ateam init` and checked by `ateam doctor`.

## Adoption scope

ATeam is an opinionated experimentation lab primarily grounded in Go development. Initialization uses the same templates for all project languages; it does not detect language support or create a Taskfile. Review and adapt these instructions before adoption. Go mutation checks require non-test .go source; verification targets belong to the adopting project. Shortcut scanning covers only .go, .ts, .js, .svelte, .sh, .yml, and .yaml files (excluding Go tests and .test.ts files). Other languages are not validated as complete workflows. Ponytail modes change injected guidance, not model settings or guaranteed compliance. Benchmark self-tests validate reference fixtures, not improved agent performance.

See [the adoption guide](../docs/adoption.md) for command dependencies, scanner limits, and verification setup. The Go/Svelte gates below describe this repository; adopting projects must define suitable equivalents.

Read [how the harness runs](../docs/hook-flow.md) for event effects, injected context, design opinions, and failure behavior.

## Shared Skills

Canonical skills live in `.agents/skills/<name>/SKILL.md`:

- [pickup](skills/pickup/SKILL.md): check live git branch, `HEAD` SHA, worktrees, GitHub/Gitea issues and PRs, open `Hold:` items, and any commits since the last handoff.
- [handoff](skills/handoff/SKILL.md): save a 5-field checkpoint (`Goal`, `Addresses`, `Constraints`, `Done when`, `Checks to run`), release the session writer lease, and print the pickup block for the next session.
- [preflight](skills/preflight/SKILL.md): run the matching `Taskfile.yml` verification checks and record test/mutation output before pushing or finishing.
- [ponytail](skills/ponytail/SKILL.md): write the smallest complete change that solves the task, track intentional limits with `// shortcut: <limit>, <when to upgrade>`, and end replies with 1–2 lines naming what was skipped and any remaining risk.
- [review-pr](skills/review-pr/SKILL.md): review one pull request as an independent, read-only reviewer on a detached `<agent>-review-pr-<n>` checkout, compare it with your own approach, and post the `reviewed-by:` / `Reviewed at <sha>` record comment that `task merge:check` reads. The manual trigger for a cross-agent review.
- [design](skills/design/SKILL.md): on the `design` track (protocol § 2 Clarify), draft `design.md` read-only: `file:line` context, at least two options per decision with the adopter seam, and owner-ruling questions marked. It drafts and never rules; the owner approves it with the proposal.

## What `ateam doctor` Checks

1. `AGENTS.md`, `CLAUDE.md`, `.agents/README.md`, `.agents/protocol.md`, `.agents/rules-index.md`, and `openspec/config.yaml` exist and are non-empty.
2. `CLAUDE.md` imports `@AGENTS.md`, stays within 10 lines, and does not define its own section headings or rule tables.
3. `AGENTS.md` stays strictly under 24,000 bytes and matches `.agents/rules-index.md` in numbered rule sections and row counts.
4. Every canonical skill in `.agents/skills/<name>/SKILL.md` has a matching thin pointer in `.claude/skills/<name>/SKILL.md` and `.gemini/commands/<name>.toml`.
5. `.claude/settings.json`, `.codex/hooks.json`, and `.gemini/settings.json` wire all four lifecycle events (`session-start`, `before-prompt`, `pre-compact`, `turn-end`) with the expected `--agent claude|codex|gemini` identity, and `.agents/hooks.json` wires `session-start`, `before-prompt`, `turn-end` (`--agent agy`) for Antigravity.
6. Project MCP registration is parsed separately from `.mcp.json`, `.codex/config.toml`, `.gemini/settings.json`, and `.agents/plugins/ateam/` (`plugin.json` and `mcp_config.json`). This is local structure validation, not live client connection evidence. See [MCP setup and verification](../docs/mcp.md).
7. The running `ateam` binary's embedded VCS commit is not behind `HEAD`, and no duplicate `ateam serve` processes are running for the repository.

## Configured model review

Optional `.agents/review-policy.json` defines exact approved models, explicit stronger-than comparisons, developer/reviewer routes, authorized reviewer/owner forge logins and required verification. No universal model ranking is bundled. A policy declaring only `model_tiers` and `effort_bands` (this repository's) is valid and configures no routes; the merge gate then needs only a reviewer not weaker by tier, then band. The role catalog and each role's default tier and band are in [ADR 0003](../docs/adr/0003-roles-and-routes.md). See [model review](../docs/model-review.md) for setup, trust boundaries and commit-bound evidence.

`ateam review setup --policy FILE` preserves custom configurations and creates portable role cards plus thin Claude skill or Gemini CLI command pointers for configured routes. Codex reads the canonical card. Operators select the runtime model explicitly; these files do not launch a model or attest its identity. Canonical [developer](contracts/developer.md) and [reviewer](contracts/reviewer.md) contracts keep implementation and read-only review separate. The [architect](contracts/architect.md) contract keeps design drafting read-only: it never implements and never rules; its routing is not configured yet. `ateam doctor` checks configured policy and instruction drift; unconfigured repositories remain compatible.
